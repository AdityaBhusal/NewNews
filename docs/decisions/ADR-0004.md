# ADR-0004: Groq behind a provider interface, with a deterministic offline stub

**Status:** Accepted

## Context

The pipeline needs AI behaviour for credibility assessment, classification, extraction of
locations/urgency, summarization, and (M2) translation and transcription. Constraints verified
in Phase 0: Groq offers a **free plan** with published rate limits (`whisper-large-v3` 20 RPM /
2K RPD; `openai/gpt-oss-120b` 30 RPM / 200K TPM) behind an OpenAI-compatible API; a `GROQ_API_KEY`
is not yet available; demos and CI must not depend on network access, spend money, or burn rate
limits. Local models were also considered because they avoid remote dependency entirely.

## Decision

Define an **`AIProvider` protocol** (`app/pipeline/ai/base.py`) with dataclass outputs
(`CredibilityAssessment(score, confidence, status, rationale[])`, `Classification(topics,
urgency)`) and select the implementation at runtime via **`AI_PROVIDER`** (`stub` | `groq`) in
`app/pipeline/ai/factory.py`:

- **`stub` (default, M1)** — a deterministic, explainable heuristic provider: no network, no
  key, same input → same output, every score adjustment emitted as a persisted rationale string.
- **`groq` (M2)** — OpenAI-compatible SDK behind the same protocol; today the factory raises
  `NotImplementedError` for `groq`, so misconfiguration fails loudly instead of silently.

Swapping stub → Groq (or OpenAI later) is an environment change, not a code change in the
pipeline.

## Alternatives considered

- **Ollama / local models** — removes remote dependency, but **Ollama is not installed** on the
  host and CPU-bound transcription/OCR would be slow; adds model downloads and GPU/CPU tuning to
  the critical path of a demo.
- **Direct Groq calls inside pipeline stages** — no indirection, but makes tests and demos
  network-dependent and rate-limited, prevents reproducible offline runs, and hard-codes one
  vendor into every stage.
- **OpenAI (or another paid API) as the M1 default** — capable, but paid and unnecessary for M1;
  the interface keeps it a later configuration option.

## Consequences

- Dev, demo, and CI are offline and zero-cost; `pytest` runs without secrets (integration tests
  only need `TEST_DATABASE_URL`).
- Rationale strings give the assessment an explainable audit trail — stored in
  `validation_rationale` and audit detail, reinforcing "AI outputs are assessments, not proof of
  truth".
- The stub is **not** a credibility analysis — its thresholds are keyword heuristics; switching
  to `groq` in M2 is expected to change score distributions, so routing thresholds
  (`CREDIBILITY_VERIFIED_THRESHOLD=0.75`, `MIN_ROUTING_CONFIDENCE=0.4`) must be re-tuned then.
- `StubProvider.translate()` raises `NotImplementedError` (ships with Groq in M2); the factory
  caches the chosen provider per process, so `AI_PROVIDER` changes require a restart.
