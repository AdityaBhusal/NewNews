# ADR-0001: Python 3.13 + FastAPI over C#/ASP.NET Core and Node/TypeScript

**Status:** Accepted

## Context

NewNews is greenfield with a cross-stack team: the team's background includes C#/.NET, and
Node/TypeScript was available on the host (Node 20 and the .NET 10 SDK are both installed, as is
Python 3.13.7). The workload is an AI-centric pipeline: LLM calls for credibility assessment and
classification, Whisper speech-to-text, OCR, media handling (ffmpeg), an async web API with SSE
streaming, and a background worker. .NET 10 is LTS (supported to Nov 2028) and ASP.NET Core is a
mature, high-performance framework.

## Decision

Use **Python 3.13** with **FastAPI 0.143 + Uvicorn** (Pydantic v2 for request/response
validation, OpenAPI/Swagger out of the box), SQLAlchemy 2.0 async for persistence, and SSE via
Starlette's `StreamingResponse`.

## Alternatives considered

- **C# / ASP.NET Core (.NET 10)** — genuinely strong: performance, static typing, and real team
  experience. Rejected because the AI/media library ecosystem (OpenAI-compatible SDKs,
  `pytesseract`, Whisper clients, ffmpeg bindings) is much richer and more current in Python,
  and on explicit project direction to work in the Python AI ecosystem.
- **Node / TypeScript** — good async story and first-class SSE/WebSockets, but weaker
  media/ML tooling for transcription, OCR, and media processing.

## Consequences

- Richest access to AI/media libraries; Groq's OpenAI-compatible SDK works directly (ADR-0004).
- FastAPI gives async endpoints, dependency-injected auth, and generated OpenAPI docs for the
  assessment demo at zero extra cost.
- Static typing is opt-in (type hints + Pydantic models + ruff); weaker compile-time guarantees
  than C# — mitigated by Pydantic boundary validation and tests.
- Runtime performance is below ASP.NET Core — irrelevant at prototype scale.
- Team shifts away from its primary language stack; documentation must be extra explicit
  (partly why `docs/` and ADRs exist).
